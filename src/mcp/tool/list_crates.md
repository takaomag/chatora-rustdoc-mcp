List the crates of the project: its workspace members and their dependencies, at the versions that its Cargo.lock resolves (not those that the manifests declare), with where each comes from, whether the build for the target uses it, the features it is built with, and whether its rustdoc JSON is in the cache. Answers questions such as "what does this project depend on, and at which versions?" or "why is `windows-sys` 0.52 in my dependencies?".

`project` is the workspace (its directory or Cargo.toml), by default the project Claude Code was opened in. `target` is the target triple whose build is looked at, by default the host's. `scope` is `direct` (the default: the members and the crates they depend on directly) or `all` (every package of the graph). With `crate`, only the crates of that name are listed, each with `used_by`: the chains of dependencies from a member down to it, shortest first, as `cargo tree -i` shows them. `limit` is the most crates in a page (default 100, at most 500); pass the `cursor` of the previous page, with the same other arguments, for the next.

Returns `provenance` (the project, the target, and `resolved_from`: `cargo_lock`, or `cargo_lock_raw` when `cargo metadata` failed and Cargo.lock was read directly), and `data.crates`: each with its `crate` name and `version`, `source` (`crates.io`, `path`, `git` or `registry`), `member` and `direct` when it is one, `build` (`normal`, `dev` when only the tests use it, or `none` for another target), the `features` of the normal build, and `docs_rs_json: cached` when its rustdoc JSON is in the cache. For a crate's contents call `crate_overview`; for its versions, `resolve_version`.
