Find usage examples of a Rust crate⟪ on crates.io⟫⟨ (on crates.io, this workspace's own, or a path or git dependency)⟩, or of one of its items first: the files of its `examples/` and the code blocks of its documentation. Answers questions such as "how is `tokio::sync::Mutex::lock` used?" or "are there examples of axum's `Router`?". For the API itself, call `get_item`; for how to start with the crate, `get_readme`.

`crate`, `version`⟨, `project`⟩ and `target` are as for `get_item`. `path` is an item, as for `get_item`: the examples that name it come first. `content: true` shows the text of the files too.

Returns `provenance` as `resolve_version` does, and `data.examples`, each a `file` of `examples/`, with its `name`, its absolute `path` to open, the `required_features` to run it with (`cargo run --example name --features …`) and the `lines` that name the item, or a `doc` block, with its `code` (the hidden lines of a doctest left out), its `attributes` (`no_run`, `ignore`), the `item` whose docs have it and that item's `source_location`. With `path`, `match` tells how each names the item: `own` (its own docs), `item_and_type` (the item and its type, as `Mutex` and `lock`), `item` (the name alone, which may be of another item) or `none`; they come in that order, files first within one, and `data.item` is its canonical path. `data.docs` is `read`, or `pending` while the documentation is had (call again after `retry_after_secs`), or `unavailable`: then the files come alone. A text longer than 20,000 characters is cut, with `truncated`. The list is paged (10 by default, `limit` up to 50): pass `next_cursor` as `cursor` for the rest.
