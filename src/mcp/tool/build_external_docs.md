Build the Rust documentation of code that the other tools do not build themselves, and keep it for them to look up: a crate that is not a dependency of the project, a version that its Cargo.lock does not have, a dependency that they say they cannot build (`reason: build_unsupported`), a crate of a git repository, the project's crates for another target, or another workspace. Building runs that code's build scripts and proc macros on this machine, outside any sandbox, so call it only for code that the user trusts. Answers questions such as "what is the API of this other workspace?" or "which items does this crate have on Windows?".

`crate` is the crate, with a version if it matters (`rand@0.9.2`), or `version` gives the version. `project` is a workspace (its directory or Cargo.toml), relative to the project Claude Code was opened in unless absolute. `git` is a repository that the crate is in, with `rev`, `branch` or `tag` (else its default branch), which is resolved anew on each call. `target` is the target triple to document for; it defaults to the project's build target for the project's crates, and to the host's for other crates.

Returns `provenance` (the workspace and the target) and `data.built`; for the project with another `target`, `data.members` tells each member built, being built or failed. When the other tools build it themselves, as they do the crates of the project Claude Code was opened in for its own build target, nothing is built: `built` is false, with `reason: query_tools_build`. Crates on docs.rs and the project's own crates need no call of this tool: look them up with `crate_overview` or `get_item` directly.
