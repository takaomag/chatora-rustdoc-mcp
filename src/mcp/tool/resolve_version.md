Tell which version of a Rust crate is meant, and whether docs.rs has its documentation: the latest release on crates.io, ⟨the version that the project's Cargo.lock resolves, ⟩or the one that a semver requirement matches. Answers questions such as "what is the latest axum?"⟨, "which tokio does this project use?"⟩ or "does serde 1.0.200 exist, and is it yanked?".

There is no need to call it before the other tools: each resolves the version itself the same way. For an item's documentation, call `get_item`.

`crate` is the crate name (`tokio`), optionally with a version (`tokio@1.47.1`); `version` may give the version instead. A version is exact (`1.47.1`), a semver requirement (`^1.47`) or `latest`. Without one, ⟨the version in the project's Cargo.lock is used (the project Claude Code was opened in, or `project`, a workspace directory or Cargo.toml inside it), or ⟩the latest release⟨ for a crate the project does not use⟩⟪ is used⟫. `target` is a target triple and defaults to ⟨the project's `build.target`, or else ⟩the host's; it is the target whose rustdoc JSON is looked for on docs.rs. Not for `std`, `core`, `alloc`, `proc_macro` and `test`, which come with the toolchain.

Returns `provenance` (the crate, version, how the version was chosen, and target) and `data`: the version; `source`, where ⟨the project gets ⟩the crate (`crates.io`⟨, `path` for a workspace member or path dependency, `git` or `registry`⟩); whether it is `yanked`; the MSRV it declares (`rust_version`); the `latest` release on crates.io; and `docs_rs_json`: `available`, `no_json` (docs.rs has none for this release; it has rustdoc JSON only for releases built on or after 2025-05-23), `no_target_json` (none for this target), ⟨`not_on_docs_rs` (the project's copy is not the crates.io release) or ⟩`unknown`.
