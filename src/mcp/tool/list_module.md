List what a module of a Rust crate has: its items and the re-exports in it, each with a one-line signature, the features it needs⟨ and whether the project's build has it⟩. With `recursive`, the submodules' items too, which with `detail=brief` outlines a crate's whole public API. Answers questions such as "what is in `axum::routing`?" or "what does this module re-export?". Results come a page at a time: `page.next_cursor` gets the rest.

`crate`, `version`⟨, `project`⟩ and `target` are as for `get_item`⟨; this workspace's crates are built here, private items too⟩. `path` is the module (`axum::routing`), or the crate root if left out; a module re-exported from another crate (`reqwest::header`) is listed from that crate. `recursive` lists submodules down to `depth` levels (default 3, at most 8). `kind` keeps only items of these kinds: one or a list of module, struct, enum, union, trait, trait_alias, function, type_alias, constant, static, macro, proc_attribute, proc_derive, primitive, extern_crate, extern_type, variant (and method, assoc_const and assoc_type, which only `search_items` finds). `detail` is `brief` (the default here: path, kind, signature line, features), `normal` (also the where clause and the first paragraph of the docs) or `full`. `limit` is the most items in a page (default 50, at most 200); pass the `cursor` of the previous page, with the same other arguments, for the next.

Returns `provenance` as `get_item` does, `data` with the module's `path` and its `items` (each at the path it is listed at, with `canonical` when that differs, and `reexport_of` for another crate's item), and `page` (`shown`, `total`, `has_more`, `next_cursor`). Methods and associated items are not listed; `get_item` shows each.
