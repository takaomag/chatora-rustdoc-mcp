List the features of a Rust crate: what each enables, what enables it, and which `default` enables. Answers questions such as "which feature of axum do I enable for websockets?" or "what does tokio's `full` enable?".

`crate`, `version`⟨, `project`⟩ and `target` are as for `get_item`. Pass `feature` for one feature alone. The features are those of the crate's `[features]` and one for each optional dependency that no feature names as `dep:x`, read from the crates.io index's line of a release⟨, or of the project's other crates from `cargo metadata`, or of a crate of git from its `Cargo.toml`⟩.

Returns `provenance` as `resolve_version` does, `data.default` (the crate's features that `default` enables, through others too), and `data.features`, each with `name`; `enables`, its values as written; `closure`, the crate's features it enables through others too; `dependencies`, what it and its closure enable of dependencies (`dep:x`, `x/f`, and `x?/f`, which enables `f` only if `x` is enabled otherwise); `enabled_by`, the features that enable it through others too; `default` if `default` enables it; `implicit` for one that an optional dependency makes; ⟪and ⟫`in_docs: false`, when the documentation's build is known, for one that it did not enable, whose items are not in it⟨; and, of a version that the project uses, `enabled_in_project`, whether its build enables it, or `enabled_in_dev_only`⟩. A list longer than 50 is cut, with its `_total`. To enable a feature, pass it or one of its `enabled_by` to Cargo. The list is paged: pass `next_cursor` as `cursor` for the rest. `data.docs_rs_json` tells whether docs.rs has the documentation, as `resolve_version` does.

Neither the documentation nor a build is needed. For the items that need a feature, call `get_item` or `search_items`.
