Look up one item of a Rust crate⟨ (this workspace's own, a dependency, or one on docs.rs)⟩⟪ from docs.rs⟫, or of the standard library: its signature, where clause, fields or variants, documentation, deprecation, and where it is defined. Answers questions such as "what is the signature of `tokio::sync::Mutex::lock` in tokio 1.47.1?"⟪ or⟫⟨,⟩ "what fields does this struct have?"⟨ or "what does a type of this workspace hold?"⟩. For the methods or traits of a type, call `list_methods` or `list_impls`; to find a path, `search_items`.

`crate` is the crate name (`tokio`), optionally with a version (`tokio@1.47.1`); `version` may give the version instead. A version is exact (`1.47.1`, not `^1.47.1`), a semver requirement (`^1.47`) or `latest`; without one, ⟨the version in the Cargo.lock of the project (the one Claude Code was opened in, or `project`) is used, or ⟩the latest release⟨ for a crate the project does not use⟩⟪ is used⟫. ⟨Workspace members are built here, private items too (with `visibility`; `crate::a::Item` if not public); so are most dependencies that docs.rs lacks. ⟩`path` is the path of the item, such as `tokio::sync::Mutex`, `sync::Mutex` (the crate name is added), or `tokio::sync::Mutex::lock` for a method, an associated item or an enum variant. `target` is a target triple and defaults to ⟨the project's `build.target` for its crates, else ⟩the host's; docs.rs builds most releases since 2026-05-01 for one target only, so another target may have no data. For `std`, `core`, `alloc`, `proc_macro` and `test`, the data is that of a nightly toolchain: ⟨the one installed here, or else ⟩the latest. docs.rs has rustdoc JSON only for releases it built on or after 2025-05-23.

`detail` is `brief` (the signature only), `normal` (the default) or `full` (all the docs and attributes).

Returns `provenance` (the crate, version, how the version was chosen, target and rustdoc JSON format of the data) and `data`: the canonical path, the kind, the signature as Rust, and for an item re-exported from another crate, the crate and path to look it up with (`reexport_of`).
