Look up one item of a Rust crate from docs.rs: its signature, where clause, fields or variants, the first paragraph of its documentation, deprecation, and where it is defined. Answers questions such as "what is the signature of `tokio::sync::Mutex::lock` in tokio 1.47.1?", "what fields does this struct have?" or "which crate does this re-export come from?".

Use it for crates on crates.io instead of answering from memory. `crate` is the crate name (`tokio`), optionally with a version (`tokio@1.47.1`); `version` may give the version instead. A version is exact (`1.47.1` means exactly 1.47.1, not Cargo's `^1.47.1`), a semver requirement (`^1.47`, `~1.47`) or `latest`; without one, the version in the project's Cargo.lock is used (the project Claude Code was opened in, or `project`, a workspace directory or Cargo.toml inside it), or the latest release for a crate the project does not use. A workspace member, or a path or git dependency, is not on docs.rs and is not built yet. `path` is the path of the item, such as `tokio::sync::Mutex`, `sync::Mutex` (the crate name is added), or `tokio::sync::Mutex::lock` for a method, an associated item or an enum variant. Public paths, re-exports and definition paths all work. `target` is a target triple and defaults to the host's; docs.rs builds most releases since 2026-05-01 for one target only, so another target may have no data. Not for the standard library or for crates that are not on docs.rs. docs.rs has the data only for releases it built on or after 2025-05-23.

Returns `provenance` (the crate, version, how the version was chosen, target and rustdoc JSON format of the data) and `data`: the canonical path, the kind, the signature as Rust, and for an item re-exported from another crate, the crate and path to look it up with (`reexport_of`).
