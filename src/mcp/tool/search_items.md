Search the items of a Rust crate by name, `doc(alias)` name (finding `HashMap` by "dict", `Vec::push` by "append"), documentation and path. Answers questions such as "which function in tokio does X?" or "what is the type for Y called?" when the path is not known. Results are ranked and come a page at a time; a result missing from a page is not proof that no such item exists: `page.next_cursor` gets more.

`crate` is required for now (the crate name, optionally `name@version`), with `version`, `project` and `target` as for `get_item`: without a version, the project's Cargo.lock decides it, or else the latest release; docs.rs has rustdoc JSON only for releases it built on or after 2025-05-23. `query` is the words or path to look for (`Mutex`, `sync::Mutex`, `spawn blocking`); words are matched whole, not as prefixes. `fields` keeps the search to some of `name`, `alias`, `docs` and `path` (default: all). `kind` keeps only items of these kinds, as for `list_module`. `detail` is `brief` (the default: path, kind, signature line, features and the first sentence of the docs) or `normal`. Without `limit`, the first page ends where the scores drop; `limit` (at most 200) sets the size of each page, and `cursor` gets the next with the same other arguments.

Ranking puts first a path that ends as the query does, then a name equal to the query, then the query's last word as a name, then a `doc(alias)` name, then other matches by BM25. Unstable items of std are left out. For std, items re-exported from core and alloc are found by name and path; `get_item` follows them.

Returns `provenance` as `get_item` does, `data` with the `query`, the `items` found (each at its canonical path, with `reexport_of` for another crate's item) and, when nothing is found, `did_you_mean` (paths of items with similar names), and `page`.
